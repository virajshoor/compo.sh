02 / SMALL BY DESIGN

Less machinery.
More Mac.

Native from the start

Swift, AppKit and SwiftUI. No Electron shell. No third-party runtime dependencies.

Works when things change

Window events drive tiling, with bounded retries while newly launched windows become ready. No idle window polling. Window placement is instant by default; drag previews stay visible.

Access, explained

Accessibility lets compo.sh move and resize windows. It never records your screen. No SIP changes required.

A switch, not a commitment

Pause anytime. Snap Edges hands native edge tiling back to macOS when switched off, paused or quit. Launch at login stays optional.

Does it replace the macOS compositor?

No. compo.sh arranges standard windows using Accessibility. macOS keeps rendering, native fullscreen and Spaces. Saved workspaces restore window arrangements; instant desktop cuts use an undocumented Dock protocol that may need fixes after macOS updates.

What happens to native edge snapping?

While Automatic Tiling and Snap Edges are enabled, compo.sh saves your macOS edge tiling preferences and disables the competing previews. It restores your previous preferences on disable, pause or normal quit. These macOS preference keys are undocumented and may change with OS updates.

Can every app fit every layout?

Some apps enforce minimum window sizes or refuse Accessibility moves. Float those windows or use fewer panes. Dialogs, minimized windows and native fullscreen windows are excluded. Quarter snaps reserve the opposite half for other windows.

Which Macs and app versions does this support?

The universal app supports Apple silicon and Intel on macOS 13 or later. Instant desktop switching requires macOS 26.6 or later; other supported systems retain native desktop shortcuts. Downloads always point to the latest GitHub release, so this site does not need rebuilding for each app version. Browse all versions and their release notes for requirements specific to an older build.

Is this a finished release?

compo.sh is beta software. Swift tests cover geometry, workspace validation, shortcuts and recovery logic; real desktop behavior still needs hands-on testing across apps and displays. Keep launch at login off until you are comfortable with its behavior.
